# Fleetwise · 司机智能排班交互原型

依据 `../docs/智能排班-需求文档.md` 制作，采用原生 HTML、CSS、JavaScript，无需安装前端依赖或连接服务端。

## 与当前需求基线的差异

2026-11-02 第一、二阶段设计确认了以下调整，已同步至需求文档 V1.2 和 [功能模块梳理](../docs/design/01.功能模块梳理.md)。本轮仅更新文档，原型代码尚未同步；以下“页面与交互”描述仍是现有原型的实际行为。技术方案见 [整体架构设计](../docs/design/02.整体架构设计.md)，已于同日通过用户审核。

- 正式确认改为整个采集计划全部日期统一提交，不再支持从多日计划中选择一天或部分日期确认。任一待确认日失败，整次新增确认全部回滚；每天非空合法但有需求缺口时仍可确认。
- 未来单日正式修改及单日取消保留。取消后从整计划入口再确认，已有有效日期只读保留，包括过去已确认日期；所有待确认未来日期一起成功或回滚。
- 未来已确认日允许同次调整需求与受影响排班，统一展示差异、校验和保存；原型目前分开编辑。
- 同模式容量利用率按全部符合条件的可用容量计算，包含未使用班次；原型目前仅以已安排班次容量为分母。

- 统计需求包含筛选范围内全部计划需求，包括未确认、仅有草稿及已取消日期；正式已分配量只计有效安排。
- 类别改名后，正式排班及变更历史保留原名；类别被需求、草稿或正式历史引用时禁止删除。
- Agent 资料逐条写入，不开放同模块多条或跨模块批量修改；整计划确认及已确认日联合变更继续按专用业务规则处理。
- 新版本为 Windows 本机免登录、固定车队长身份；原型的模拟登录、退出只保留为旧交互说明。

上述后三项业务口径已解决第一阶段 Q01—Q03。原型的本地演示保存不代替新版本 SQLite 保存；新版本不迁移旧库，旧文件保留，首次使用为空业务数据。

第三阶段另确认：可用容量只看车辆自身条件，不扣减司机不足或已排另一模式；计划日期的容量基准未来刷新、当天及过去冻结；草稿及正式历史均保护资源删除，纯统计快照不阻止；类别改名刷新未来需求与草稿，锁定日期需求及已有正式历史保留原名。详见 [数据库设计 B01—B04](../docs/design/03.数据库设计.md)，13 表精简方案及 SQL 已于 2026-11-02 通过用户审核，原型代码仍未修改。

## 打开方式

直接使用 Chrome、Edge 等现代浏览器打开本目录的 `index.html`。所有样式、图标和脚本均为本地文件，无 CDN、字体或图片网络依赖。

也可在项目目录启动仅用于提供静态文件的服务：

```powershell
.\.venv\Scripts\python.exe -m http.server 8088 --bind 127.0.0.1 --directory prototype
```

浏览器访问 <http://127.0.0.1:8088>。静态文件服务不包含业务接口。

## 页面与交互

| 页面 | 可体验内容 |
| --- | --- |
| 排班工作台 | 日期切换、TAG/ROAD 筛选、车辆班次看板与明细列表、生成预览、编辑及增删任务包、单日与多日确认、取消正式排班 |
| 采集计划 | 三步创建向导、日期重叠提示、默认每日需求、指定日期独立需求、计划详情及需求修改、采集类别维护 |
| 车队资源 | 司机与车辆切换、搜索及等级/可用状态筛选、资料增删改、班次资格与容量、请假和维修登记、历史引用保护 |
| 排班历史 | 有效安排与取消状态、历史只读、原始安排及变更记录 |
| 统计分析 | 正式数据统计、独立 TAG/ROAD 图表、司机班次数、车辆使用情况及日期筛选 |
| 操作记录 | 页面与 Agent 入口、操作成功及失败、完整变更详情、关键词搜索 |
| Agent 侧栏 | 预设自然语言查询、需求澄清、生成预览、司机效率修改及排班确认/取消摘要 |

## 推荐体验顺序

1. 默认进入排班工作台，查看 11 月 4 日预览，点击任意任务包编辑。
2. 故意把任务量改到超过容量，查看拒绝提示，确认原预览保留。
3. 确认本日排班，检查“排班历史”“统计分析”“操作记录”的同步变化。
4. 再编辑正式任务包，核对完整修改前后差异，保存后查看历史。
5. 尝试批量确认，其中包含尚未生成预览的日期，体验整批拒绝；生成所选日期后再确认。
6. 在车队资源为已经排班的司机登记请假，查看影响日期提示。
7. 点击 Agent 建议问题，执行“将张三的效率等级改为高”，在确认之前核对资源数据未变。
8. 右上角“演示日期”打开设置，体验资源不足日、历史锁定日和空白初始化。

## 原型范围

- 页面始终标记“交互原型”。为便于评审，默认载入独立示例：24 辆车、60 位司机、一份未来多日计划和一份历史计划。可在演示设置选择“从空白开始”体验需求 R55 的空白业务状态。
- 演示业务日期固定为 **2026-11-02**，可以在设置中更改。日期锁定以该演示日期为准，不把它冒充真实系统当前时间。
- 数据仅写入浏览器 `localStorage`，键为 `fleetwise.prototype.v1`；不会读写项目现有数据库。恢复示例和清空操作只影响本原型数据。
- 任务分配为本地演示，用于串联交互及展示容量、资源冲突、日期锁定和批量提交反馈，不代表正式排班算法、全局最优求解或性能验收结果。
- Agent 使用预设意图与当前本地数据，没有调用 DeepSeek 或任何大模型。未覆盖的表达会提示支持范围，不虚构执行成功。
- 登录只演示单一车队长角色的进入/退出交互，不执行真实身份认证。
- 通知仅保留 TODO 和“未接入”状态，不发送、不模拟成功、不运行重试。
- 没有司机反馈、实际采集完成率、任意 SQL、服务端接口及真实权限逻辑。
- 演示数据保存在当前浏览器及打开来源中；切换浏览器、端口、无痕模式或清理存储后，数据不会共享。

## 文件

- `index.html`：页面外壳、导航、图标及弹窗容器。
- `styles.css`：设计样式、响应式布局、交互与减少动态效果适配。
- `app.js`：本地演示数据、页面渲染、表单、模拟约束、确认及 Agent 交互。
- `tests/prototype_smoke.py`：无头浏览器关键流程验证及截图。
