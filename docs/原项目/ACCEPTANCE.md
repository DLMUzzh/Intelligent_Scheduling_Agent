# 开发与验收记录

验收日期：2026-10-27。

## 已实现范围

- FastAPI + SQLAlchemy + SQLite 后端，22 张业务表，统一 JSON 响应、OpenAPI、参数校验和可选访问密钥。
- Jinja2 页面与独立 CSS / JavaScript，业务数据经 API 访问，支持桌面与手机宽度。
- 采集计划、日期范围展开、每日差异需求；司机效率与班次资格；车辆分班容量；资源不可用日期。
- 独立 Protocol 排班策略、GREEDY_V1、覆盖率、容量利用率、效率等级分布、同等级累计工作量离散指标及生成耗时。
- 预览持久化、版本控制、增删改校验、放弃、有效期、重叠日期复用。
- 单日 / 多日原子确认、跨计划冲突校验、数据库唯一约束、幂等键、正式排班与统计。
- 事务内创建通知，事务后模拟发送，失败记录与重试、PENDING 恢复、审计记录。
- Windows 启动脚本、锁定依赖、数据库初始 SQL、OpenAPI 静态导出、API 接入说明。

## 明确保留的范围

- `app/agent/` 与 `app/agent/tools/` 没有任何实现文件，按本次用户要求留待后续开发。
- 不含 DeepSeek、Tool Calling、Agent 会话 / 操作确认 API、通用数据库 Agent CRUD 或任意 SQL 工具。
- 通知为控制台模拟，不是短信、飞书或企业微信送达。
- GREEDY_V1 是启发式策略，不声明全局最优；优化策略通过 Protocol 后续扩展。
- 当前为本地共享管理模式，未实现多用户账户与角色权限；既有数据库迁移也留待后续版本引入。
