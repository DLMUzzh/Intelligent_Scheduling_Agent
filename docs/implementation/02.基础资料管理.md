## 实施基线

开发前已阅读 AGENTS.md、docs/rules 和五份设计文档，并检查旧服务、模型、接口、页面原型及第一阶段公共能力。修改前 Git 工作区干净，基线回归为 149 项通过。

## API 与数据结构

新增 Q02 GET /api/v1/collection-categories 和 Q07—Q12 的司机、车辆及不可用记录列表/详情。写入接入 W01/W04，使用 CREATE/UPDATE/DELETE_CATEGORY、DRIVER、VEHICLE、UNAVAILABILITY 共十二类动作。启停属于司机或车辆的 UPDATE patch，取消不可用记录使用 DELETE_UNAVAILABILITY。

分页结构、七字段响应、错误码、Id/Version/容量十进制字符串和 0/1 标记均采用既定契约。前端道路容量按公里填写，精确转为整数米，六项字段名与数据库一致。查询附带一致性 data_revision，表单使用实际展示的版本准备操作。

数据库仍采用已审核的 13 表、137 字段及 12 个显式索引，结构版本为 0001_foundation。本阶段迁移文件变更数为零，资料、不可用记录、待确认操作、全局修订及审计使用既有实体。运行旧库和默认新库的校验结果见验证记录。

## 核心规则及一致性

1. 类别按去首尾空白后的名称和模式精确比较。创建和更名在准备及执行时检查唯一性，数据库 UNIQUE 作为最终防线。创建后模式只读。
2. 司机允许同名及同电话，高中低效率与三班资格使用明确枚举和整数标记，三班资格可全部关闭。
3. 车牌展示值去首尾空白，plate_key 去全部空白并转大写，服务端生成并检查唯一。六容量采用 0 至 9223372036854775807 的规范整数字符串，拒绝浮点、布尔、负数、科学计数和溢出。页面公里值通过 BigInt 转换，精度到米。
4. 不可用记录新增须所属资源版本，编辑和取消另须记录版本。编辑保留所属资源，日期成对修改。原区间及新完整区间均为未来，执行提交前再次校验业务日期。重叠记录按覆盖并集处理。
5. 删除类别检查需求、两类明细、草稿依据及所有正式事件前后需求与任务引用。删除司机车辆检查两类任务包和所有正式任务历史。纯容量历史允许保留已删除车辆编号，无排班引用的资源删除会展示并清理关联不可用记录。
6. 影响检查只读取未来 ACTIVE / FORMAL，收集全部非法日期。司机停用、撤销所需资格、请假、车辆停用、维修或降低到包内类别合计以下的容量均会整体拒绝，历史日期按冻结规则保留。
7. 类别改名刷新未来需求和 DRAFT 名称并推进日期/计划版本。资料变化按资源输入依赖保守标记未来草稿，不可用区间变更限定旧新区间内草稿。车辆变化刷新发生容量内容变化的全部未来日期基准，冻结日期保留已存数组。
8. 关联差异在准备时完整冻结。新车尚未分配编号时，关联容量预览的 vehicle_id 为 null，执行时填入实际生成编号，审计记录实际值。主对象自动编号同样通过公共确认投影处理。
9. JSON 读取按 schema_version / snapshot_schema_version 校验。正式历史使用明确嵌套结构，容量数组校验每车唯一完整三班。草稿 validation_basis 按设计允许保存额外输入，类别引用通过 collection_category_id 严格识别。
10. BEGIN IMMEDIATE 内重新检查冻结内容、版本、唯一性和业务条件。主对象、资源/日期/计划版本、容量、草稿标记、全局修订、成功审计及操作终态同事务提交。失败整体回滚，持久幂等和提交不明核实继续复用第一阶段实现。

页面恢复使用 sessionStorage 保存当前标签页的原请求和执行意图，服务器业务操作记录负责持久事实。核实到 PENDING 时保持未知执行与原操作绑定，用户可继续查询或重放同一操作。结果终态才解锁后续新请求。
