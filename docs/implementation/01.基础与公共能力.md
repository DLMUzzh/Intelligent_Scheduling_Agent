### 公共服务接入约定

业务适配器提供 validate_payload、prepare、execute。prepare 在 SQLite query_only 模式下读取，返回完整摘要、解析结果和完整依赖版本。execute 参与当前 Session，返回实际结果及公开 after，提交由公共服务负责。对象版本递增使用公共 advance_object_version，业务修订由公共服务一次推进。

状态仅为 PENDING、SUCCEEDED、FAILED。待确认内容保存在现有 JSON 字段，确定性对象键排序和数组顺序绑定 hash。执行核验冻结内容及重新解析结果，终态重放先于版本校验。成功业务、审计、版本和终态在一个 BEGIN IMMEDIATE 事务中提交。明确回滚的失败在独立短事务记录，落库前再次检查终态。

Prepare 同时拒绝直接 SQL 写入和待 flush 的 ORM 变更。确认比较允许将新建对象的 null id 替换为真实服务端编号，其他业务值与既有对象编号严格一致，审计保存实际编号。版本冲突失败时读取最新对象状态记录审计，准备提交确认丢失时也会重新检查持久化输入绑定。

本阶段不向生产注册业务适配器，测试专用适配器仅存在 tests/foundation/conftest.py，经过与生产相同的接口与公共服务验证。后续接入计算型业务时，计算与最终写事务之间的分离按设计 02 第 5.1 节、04 第 6.4 节落实，公共写事务内只执行最终持久化与校验。
